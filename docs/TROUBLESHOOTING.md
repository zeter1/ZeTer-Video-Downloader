# Диагностика и устранение неполадок

[← Документация](README.md) · [Быстрый старт](../README.md#быстрый-старт) · [Поддержка](../SUPPORT.md) · [Сообщить об ошибке](https://github.com/zeter1/Universal-Video-Downloader/issues/new/choose)

Инструкция относится к текущему приложению, где видео сохраняется в **MP4 не выше 1080p**, а MP3 создаётся **после успешно скачанного видео**. Гарантировать работу конкретного сайта нельзя: её определяют сеть, доступ к источнику и yt-dlp.

## 1. Определите режим запуска

| Готовый Windows EXE | Запуск из исходников |
| --- | --- |
| Скачан из [GitHub Releases](https://github.com/zeter1/Universal-Video-Downloader/releases), Windows x64 | Запущен командой `python video_downloader.py` |
| yt-dlp, FFmpeg, ffprobe и Deno **уже внутри EXE** | Требуются Python-зависимости, FFmpeg/ffprobe в `PATH`, а для отдельных сайтов может понадобиться Deno/Node.js |
| `pip install -U yt-dlp` не изменяет встроенный yt-dlp | `python -m pip install -U yt-dlp` обновляет пакет **в используемом Python-окружении** |
| Служебные файлы хранятся рядом с EXE | Служебные файлы хранятся в корне репозитория |

Не помещайте портативный EXE в `Program Files` или каталог без права записи. Выбирайте отдельную папку пользователя, например `Документы\Universal-Video-Downloader`; настройки, история и журналы хранятся рядом с программой.

## 2. Проверьте симптом

| Симптом | Последовательность действий |
| --- | --- |
| Ссылка не начинает скачиваться | Проверьте URL в браузере и интернет; вводите **по одной ссылке в строке**, проверьте папку назначения и сообщения в интерфейсе |
| YouTube: 403, 429, ошибка формата, EJS / timeout | Проверьте доступность сайта и ограничения сети; в EXE используйте свежую сборку из Releases, из исходников — актуальный yt-dlp и доступный JS runtime; изучите конкретный ответ в логе |
| Качество меньше 1080p | Проверьте доступность исходного потока; 1080p — **максимум и предпочтение**, а не гарантия. Высота выходного файла проверяется через ffprobe |
| MP4 есть, MP3 нет | Сначала проверьте, завершилась ли обработка, была ли в источнике аудиодорожка, есть ли ошибки FFmpeg и валидации MP3 |
| «Ссылка пропущена» | Ищите дубль в очереди или запись об уже скачанном видео в истории; не очищайте историю, пока не выяснили причину |
| HTML-плейлист не распознан | Сохраните страницу плейлиста YouTube в HTML повторно и проверьте, что в нём реально присутствуют записи видео; импорт зависит от HTML-структуры страницы |
| Объединение / разбиение MP3 не завершилось | Проверьте вкладку ошибок, папку `Разбивка аудио`, исходные MP3 и свободное место; промежуточные `.merge_*`/`.split_*` могут содержать материалы восстановления — **не удаляйте их до разбора** |
| SmartScreen предупреждает об EXE | Проверьте источник [Releases](https://github.com/zeter1/Universal-Video-Downloader/releases) и SHA-256. Сборки не имеют коммерческой цифровой подписи; само предупреждение не доказывает безопасность файла |
| Приложение не сохраняет настройки | Убедитесь, что рядом с EXE можно создавать каталоги и писать в них; проверьте `Настройки/settings.json` |
| Новая версия не устанавливается | Дождитесь завершения загрузок, проверьте права записи к EXE и наличие блокирующего процесса; изучите `Обновления/build-.../update-error.log`, если он создан; при необходимости замените EXE вручную |

**Не обещаем:** обход DRM, ограничений платного/приватного контента, авторизации и правил сервисов. Загружайте только разрешённый вам контент.

## 3. Если проблема связана с обновлением

1. В интерфейсе нажмите **«Проверить обновления»** или используйте проверку при запуске, если она включена.
2. Сравнение работает для Windows EXE с корректным `build-<7 символов commit>` внутри `build_info.json`. Старые сборки без идентификатора нужно **один раз заменить вручную**.
3. Обновление проверяет опубликованные GitHub Releases и SHA-256 по метаданным ассета, после чего запрашивает согласие на установку. Приложение не должно заменяться во время загрузки.
4. Если Github недоступен или выпущенный EXE невозможно проверить, не используйте непроверенные исполняемые файлы из сторонних источников. Скачайте EXE из [Releases](https://github.com/zeter1/Universal-Video-Downloader/releases) вручную.
5. При ручной замене **не удаляйте** `Настройки/`, `Логи скачивания/`, `Логи проблем/`, `История ссылок/` и скачанные медиафайлы. Не смешивайте данные с временными каталогами PyInstaller.

Подробнее об идентификаторах релизов, ручной проверке SHA-256 и сборке: [RELEASE_PROCESS.md](RELEASE_PROCESS.md).

## 4. Где искать доказательства сбоя

**Рядом с EXE** (или в корне проекта для исходников):

| Путь | Для чего |
| --- | --- |
| `Логи скачивания/download_log.txt` | Основной журнал действий |
| `Логи проблем/latest_run.json` | Указатель на последний диагностический запуск |
| `Логи проблем/latest_session.json` | Указатель на последнюю сессию |
| `Логи проблем/Сессии/<сессия>/session_summary.md` | Человекочитаемый итог |
| `Логи проблем/Сессии/<сессия>/events.jsonl` | События по этапам |
| `Логи проблем/Сессии/<сессия>/incidents.jsonl` | Классифицированные инциденты |
| `Логи проблем/Сессии/<сессия>/manifest.json` | Структура и метаданные сессии |

Файлы `Логи проблем` могут отсутствовать, если подробное логирование отключено; записи и структура меняются в зависимости от стадии сбоя. Если запись указателя не удалась, смотрите соответствующую папку сессии и аварийный журнал `Логи проблем/emergency_problem_log.jsonl`.

Для разработчиков: валидатор запускается из корня проекта командой `python problem_log_validator.py` (последний запуск) или `python problem_log_validator.py "путь/к/сессии"`. Он **проверяет формат/согласованность логов**, но не доказывает, что скачивание прошло успешно. Валидация встроенных примеров: `python problem_log_validator.py --examples`.

## 5. Перед созданием issue

Укажите **ревизию `build-...` или commit**, Windows, сайт (без приватного URL), последовательность воспроизведения, ожидаемый и фактический результат, проблему загрузки/конвертации/обновления и обезличенные фрагменты журналов.

**Проверьте приватность вложений:** даже если есть автоматическая маскировка, вручную удалите cookie, токены, query-параметры временных ссылок, логины, прокси с паролями, имена личных каталогов. Не публикуйте полноценную папку `Логи проблем` без проверки. Уязвимости сообщайте по [SECURITY.md](../SECURITY.md), не через публичные issues.
